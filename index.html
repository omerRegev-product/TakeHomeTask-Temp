Low urgency. Client raised it last. Becomes available once the detection layer is in place and lane data is accumulating.

Reporting

Real problem. Different intervention type — requires human judgment, not agent automation. Out of scope for this build, not out of scope permanently.

High impact when it matters. A readiness play: critical when volumes grow or regulators audit. Requires regulatory approval to automate actions — not our constraint to solve today.

§3.4 — Human-in-the-Loop

How the human stays in control.

Pre-approved
Auto-execute
Routine decisions within guardrails. Agent acts, logs it, outcome monitored. No human needed unless the outcome check flags an issue.
Small decisions
Ops Team Member approval
Team review
Certified for limited decisions. Agent proposes and a team member approves in Slack or the UI. Ops lead not involved.
Medium decisions
Ops Lead approval
Lead review
High-stakes, novel, or high-cost. Agent proposes with: attribution, confidence, cost, alternatives. One action to approve. Not a workflow.
Large decisions
Evaluations monitor the pre-approved tier. The agent schedules outcome checks on its own actions. Human overrides are logged as signal and feed into retraining. Autonomy stays safe because performance is continuously measured.
Thresholds are configurable per customer. What counts as a "Small" auto-execute decision for one customer may be a "Large" (ops-lead approval) for another. Emailing a warehouse might auto-execute for a high-trust customer and require sign-off for a new one. The tier model is a policy — each customer tunes it.

§3.6 — Evals & Learning

Four feedback loops. How agents get better.

Implicit Reaction
Agent detects when a human reverses its decision. Holds as a weak signal. If the pattern repeats, it flags for review and adjusts behavior. No explicit feedback required.
Explicit Directive
Ops lead flags: "this action was wrong." High-confidence signal. Feeds directly into agent rules. One tap on any log entry to flag. Optional free-text to explain.
Outcome Eval
Did the action actually move the metric? Resolution Agent: did OOR rate drop on the next N shipments? Prevention: failure rate with vs. without intervention? The agent schedules its own follow-up check — appears in the activity log days later.
Cross-Entity Learning
← the moat
What worked on Lane A becomes a recommendation for Lane B. Pattern on one product informs another with the same temp profile. Across Sensos customers: aggregate rules, not raw data — defensible for pharma. No individual customer accumulates this breadth of signal. Sensos does.

§4.2 — Design Intent

Four things the tool does for the ops user.

(1)
Acts automatically
Automations and AI handle the routine. The ops user doesn't see this unless they want to. The activity log is the receipt.
(2)
Surfaces what matters
Questions. Problems. Approvals. The agent comes to the user — not the other way around. Nothing important requires going looking.
(3)
Lets the user drive
React to what agents surface. Or be proactive — invoke an agent, change a rule, adjust a threshold, steer the operation.
(4)
Lives in your tools
Agents act through the channels the ops team already uses. Alerts in Slack. Tickets in Monday or ServiceNow. No new inbox to check — the platform reaches into the existing workflow.

Appendix C — Deliberately Out of Scope

What I'd dig into next.

01 — Competitive landscape
Who else is in this space
Tive, Controlant, Sensitech/Berlinger, Roambee for telemetry. project44/FourKites for visibility. The question is whether any competitor owns all three layers: hardware telemetry, autonomous action, and a cross-customer learning network. Sensos' defensible edge lives in that combination.
Do a real teardown. Map where each player sits across the stack. Stress-test the "no competitor does all three" claim before Aviv takes it into a sales conversation.
02 — Customer's actual tool stack
What the ops team already uses
§4.2 makes a strong claim: "lives in your tools, no new inbox." But we assumed ERP/WMS + Slack + Monday/ServiceNow + Zendesk. If the real stack is different, the integration priority list changes and the design intent needs revisiting before any build starts.
Discovery call with the ops team specifically on tooling. Map which channels actually get attention and which are dead. Design the "lives in your tools" layer around what's used, not what's commonly used.
03 — Adjacent customer types
Who else has the same need
Clinical trials, biologics, vaccines, fresh food/seafood, high-value electronics, specialty chemicals — same telemetry + autonomy pattern, different temp specs and regulatory regimes. Tests the "new customer = new config, not new tools" claim directly.
Map 3–5 adjacent verticals. For each: what's the temp spec, regulatory context, which tools already apply, what's missing. Shapes the land-and-expand story for Aviv.
04 — Path to direct lane management
When agents stop proposing and start deciding
The demo shows propose→approve. The endgame is agents running lanes directly within guardrails. Hard questions: shadow mode duration, graduation criteria, which decisions graduate first, what evidence an ops lead needs to cede control, pharma regulatory constraints on autonomous actions.
Design the trust graduation model explicitly — cold-start in propose-only, measurable gates per tier. Closes the one question experienced ops leads always ask that the deck doesn't answer.
